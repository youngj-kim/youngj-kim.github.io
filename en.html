About

My background is in automotive navigation map data operations, where I have worked with road networks, search and routing quality, and pre/post-deployment validation. I focus less on building software for its own sake and more on defining the QA object, review criteria, and repeatable validation steps that make map data operations easier to inspect and explain.

The center of this portfolio is navigation data QA automation. QGIS Kakao Roadview Bridge connects field-style map review with a desktop GIS workflow. Safety Zone Change Monitoring System connects public safety-zone data changes, operational run history, and map/Roadview based review into a practical data operations project. AI coding tools may support the work, but the main value is domain knowledge, QA workflow design, and verifiable deliverables.

Safety Zone Change Monitoring System

A monitoring project that collects Korean police safety-zone Open API data, stores raw responses, normalized records, current state, and change events in PostgreSQL/PostGIS, and exposes meaningful changes through notifications and a map-based web dashboard.

09:00 KST daily run target
Polygon / Point current and change layers
v2.3 standard-link review buckets
OSM / Kakao map and Roadview dashboard
3 types child, senior, disabled zones
Implemented / Verified Scope
  • Safety-zone API collection, raw snapshot storage, and normalization pipeline
  • Separated Polygon, facility Point, and integrated zone group models
  • Change events for new, attribute change, geometry change, point change, deletion, and missing-review cases
  • Operational SQL checks and change-event verification procedures
  • Telegram/Slack notification flow that sends notifications only when relevant changes exist
  • Handling rules for empty API responses and 429 rate-limit operational issues
  • pytest coverage for API, diff, normalization, pipeline, and notification logic
Dashboard / Operations
  • Static dashboard data export using JSON/GeoJSON
  • GitHub Pages dashboard deployment: safetyzone.yjkim.dev
  • OSM/Kakao map switching and Kakao Roadview review for selected locations
  • Current layers separated by child, senior, disabled, and other safety-zone types
  • Change-state layers for new, changed, and deleted/review-needed objects with popup details
  • Recent changes, current objects, and monitoring run history tabs with search/filter UI
  • Failed runs are visible with masked sensitive query parameters in failure messages
  • Mobile review flow with collapsible bottom panel and draggable/resizable Roadview panel
  • Nationwide rollout docs for SGG codes, chunk files, and baseline loading policy
  • Prepared 09:00 KST run flow using GitHub Actions self-hosted runner or Windows scheduler
Standard Link / QGIS QA
  • Documented read contract and QC rules for the existing standard node-link PostGIS database
  • Using nationwide NGII road centerline and 0.5m simplified geometry as a supporting reference
  • Designed candidate, excluded, and coverage review views for safety-zone to road-link matching
  • v2.3 review buckets separate auto-apply candidates from manual-review candidates conservatively
  • QGIS styles and casebooks record elevated roads, underpasses, roundabouts, near-parallel false positives, and missing-link patterns
Still In Progress

The dashboard is deployed as an operational review artifact, but nationwide baseline database loading still needs chunk-based retries and stabilization due to API 429 limits. Standard-link matching is still in candidate generation and QGIS review criteria refinement, not automatic confirmed matching.
