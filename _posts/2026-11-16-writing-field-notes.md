이 글은 Field Notes를 관리하기 위한 사용 안내입니다. 새로운 글은 GitHub 웹 편집 화면에서 작성하며, 저장 후 GitHub Pages 배포가 완료되면 목록과 상세 페이지에 반영됩니다.

## 새 글 작성

1. [새 글 작성](/notes/new/) 페이지에서 **GitHub에서 새 글 작성**을 누릅니다.
2. GitHub에 로그인합니다. 저장소에 쓰기 권한이 있는 계정이 필요합니다.
3. 파일 이름은 `_posts/YYYY-MM-DD-주제.md` 형식으로 지정합니다. 주제 부분은 `qgis-roadview-workflow`처럼 짧은 영문과 하이픈을 권장합니다.
4. 템플릿의 제목, 분류, 요약과 본문을 작성합니다.
5. **Preview** 탭으로 확인한 뒤 **Commit changes**를 누릅니다. `main`에 직접 저장하거나 새 브랜치에서 만든 PR을 `main`에 병합합니다.
6. [GitHub Actions](https://github.com/youngj-kim/youngj-kim.github.io/actions)의 Pages 배포가 성공하면 발행됩니다. 반영까지 잠시 걸릴 수 있습니다.

## 글의 기본 형식

```yaml
---
title: "QGIS와 로드뷰를 연결한 이유"
category: QGIS / WORKFLOW
summary: "글 목록에 표시할 짧은 소개입니다."
lang: ko
published: true
---
```

맨 위의 `---` 두 줄 사이가 글 정보입니다. `title`과 `summary`는 따옴표 안에 작성합니다. `lang`은 한국어 `ko`, 영어 `en`을 사용합니다. 영어 글도 전체 목록에 표시되며, 한영 자동 번역은 하지 않습니다.

## Markdown으로 본문 쓰기

```markdown
## 해결하려던 문제

여기에 본문을 작성합니다. **굵은 글씨**와 *강조*를 사용할 수 있습니다.

- 검토한 데이터
- 판단 기준
- 남은 확인 사항

[프로젝트 저장소](https://github.com/youngj-kim)
```

글 제목은 위의 `title`로 표시되므로 본문은 `##`부터 시작하면 됩니다. 소스 코드는 백틱 세 개로 감싸고 언어 이름을 붙여 작성합니다.

## 이미지 넣기

1. 저장소의 `assets/posts` 폴더에서 **Add file → Upload files**로 이미지를 업로드합니다.
2. 해당 이미지가 `main`에 저장된 것을 확인합니다.
3. 본문에 다음처럼 이미지 경로를 넣습니다.

```markdown
![QGIS에서 경로를 비교하는 화면](/assets/posts/route-comparison.png)
```

파일 이름은 영문 소문자와 하이픈을 권장합니다. 이미지 설명은 화면을 보지 못하는 독자에게도 의미가 전달되도록 작성해 주세요.

## 수정·숨김·삭제

- **수정:** 글 제목 아래의 **GitHub에서 수정** 링크를 눌러 고친 뒤 저장합니다.
- **사이트에서 숨김:** `published: false`로 변경합니다. 홈페이지와 글 목록, 상세 페이지에서 제외됩니다.
- **삭제:** GitHub에서 해당 Markdown 파일을 삭제한 뒤 저장합니다. 다음 배포에 반영됩니다.

공개 저장소이므로 숨긴 글과 삭제한 글도 GitHub 변경 이력에서 확인할 수 있습니다. 비공개 초안은 로컬에 보관해 주세요.

## 발행 후 확인

발행한 글은 [전체 글 목록](/notes/)에 최신순으로 표시됩니다. 홈페이지에는 최신 글 세 개가 자동으로 표시되며, 별도로 홈페이지 HTML을 수정할 필요가 없습니다.

파일 이름이 곧 글의 날짜와 주소에 영향을 주므로 발행 후에는 가급적 이름을 유지하세요. 수정 내용이 보이지 않으면 배포 성공 여부를 확인하고 새로고침합니다. 미래 날짜의 글은 자동 예약 발행이 아니라, 해당 날짜 이후 **다음 사이트 빌드**에서 공개됩니다.
