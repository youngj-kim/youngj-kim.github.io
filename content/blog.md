\# Blog



이곳은 단순한 코드 작성 기록이 아니라, 자동차 내비게이션 데이터 운영 경험을 바탕으로 GIS, QGIS, PostGIS 기반 QA 도구를 만들어가는 과정을 기록하는 공간입니다.



글의 중심은 “어떻게 코드를 짰는가”보다 다음 질문들에 있습니다.



\* 실무에서 어떤 문제를 해결하려 했는가?

\* 이 과정이 실제 내비게이션 데이터 QA 업무와 어떤 관련이 있는가?

\* 어떤 데이터를 사용했는가?

\* 어떤 기준으로 데이터를 검증하고 결과를 판단했는가?

\* 도메인 지식을 어떻게 문제 해결 도구로 기획하고 구현했는가?



개발 자체보다 문제 정의, 데이터 흐름, QA 기준, 업무 적용 가능성을 중심으로 기록합니다.



\## Planned Posts



\### 1. QGIS Kakao Roadview 플러그인을 만든 이유



QGIS에서 지도 데이터 검수를 할 때 외부 지도와 로드뷰를 반복적으로 확인해야 하는 불편함을 정리하고, QGIS Kakao Roadview Bridge 프로젝트를 시작한 배경을 설명합니다.



\### 2. QGIS에서 외부 로드뷰를 활용한 지도 데이터 QA 워크플로우



자동차 내비게이션 지도 데이터 검수 과정에서 로드뷰가 어떤 식으로 활용되는지, 도로 형상, 회전 제한, 차선 정보, 진출입 구조를 확인하는 흐름을 정리합니다.



\### 3. QGIS 좌표와 Kakao Roadview를 동기화하는 방식



QGIS 캔버스 좌표를 EPSG:4326으로 변환하고, Kakao Map / Roadview와 연동하는 구조를 설명합니다.



\### 4. Kakao Mobility 경로 결과를 QGIS 레이어로 변환하는 이유



경로 탐색 결과와 턴바이턴 안내 지점을 QGIS 레이어로 변환하는 것이 지도 데이터 QA 관점에서 어떤 의미가 있는지 정리합니다.



\### 5. 표준노드링크 기반 보호구역 매칭 프로젝트를 시작한 이유



공공 보호구역 데이터와 표준노드링크 데이터를 PostGIS에서 공간 매칭하려는 이유와, 이 프로젝트가 내비게이션 데이터 QA 업무와 어떻게 연결되는지 설명합니다.



\### 6. 보호구역 polygon과 도로 link 매칭을 내비게이션 QA 관점에서 바라보기



직접 교차, 20m 이내 근접, 50m 이내 참고, 미매칭 후보를 분류하는 기준과 QA 검토 흐름을 정리합니다.



\### 7. 내비게이션 데이터 운영 경험을 포트폴리오 프로젝트로 바꾸는 방법



기존의 내비게이션 데이터 운영 경험을 단순 작업 이력이 아니라, 문제 정의와 QA 도구화 역량으로 전환하는 과정을 기록합니다.
